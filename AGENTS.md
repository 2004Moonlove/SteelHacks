# Project Instructions

Read `MEMORY.md` before planning or changing this project. It records the product scope, implementation contract, user preferences, and unresolved decisions for Dayfork.

- Use English for the product UI, code identifiers, comments, errors, documentation, branch names, commit messages, GitHub issues, and pull request titles and descriptions.
- Communicate with the user in Chinese unless requested otherwise.
- Target local development and demonstration first.
- Keep time and money calculations deterministic and independent of the LLM. Editing simulation parameters must not trigger model calls.
- Preserve the distinction between confirmed requirements, the working design contract, and unresolved suggestions in `MEMORY.md`.
- Update project memory when the user changes a durable requirement or a design decision is resolved.
- The user has explicitly authorized implementation of the local MVP plan. Continue the work through local verification without requesting redundant permission.
